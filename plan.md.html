TempoMind

TempoMind turns a big goal into a paced plan, resizes today's work to the owner's energy, and shares progress with a team without ever exposing how the owner feels. This page covers how it's built today and where it goes next.

Try the live demo

1 Current architecture

A single-page app with no server. Everything runs in the browser and is hosted as static files on GitHub Pages.

ModuleJob
planner.tsClassifies the goal, sizes the effort, checks capacity against the deadline, and builds milestones, tasks and 25-minute micro-steps. A rules-based stand-in for an LLM.
energy.tsRe-slices today's work only (deep work, 20-minute chunks, or one step at a time). Never moves dates.
metrics.tsProgress, pace and toPublicView(), the only shape team pages render.
store.tsOne external store, two storage keys, and live sync across tabs via the storage event.

2 Privacy boundary

The key design rule: energy data and the team never meet.

  • Team pages receive projects only, never the owner's private state.
  • Pace, hours worked and projected finish date are left out, since output levels can hint at energy.
  • The public "current task" is always the parent task, never an energy-sized micro-step.
  • Each goal has two random 128-bit link codes (view and collab), and neither is its internal id.

4 Target architecture

Where the app goes after the hackathon: a real backend, a real model, and teammates on their own devices.

  • Real LLM planner: replace the body of generatePacingPlan() with an API call that returns the same Project shape, so the UI doesn't change. The API key stays on the server.
  • Database: PostgreSQL (for example Supabase) with row-level security, so energy data is protected on the server, not just by which props a component receives.
  • Realtime: share links work across devices for real teammates, not only in other tabs of one browser.
  • Agents: opt-in email scanning turns action items into to-dos on the right person's list.

5 Roadmap

  1. Backend with sign-in and PostgreSQL; move both storage keys into tables.
  2. Swap the rules-based planner for an LLM, keeping the same output type.
  3. Realtime team view and collaborator links across devices.
  4. Learn from actual time spent to calibrate effort estimates.
  5. Opt-in email agent for action items.
